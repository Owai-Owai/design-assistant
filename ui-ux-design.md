# UI/UX Design Sub-Skill

This sub-skill handles anything related to UI design, UX design, user flows,
wireframes, interaction design, and usability.

---

## What This Sub-Skill Covers

- Writing UX documentation (user flows, journey maps, personas)
- Describing and explaining UI decisions clearly
- Reviewing screens or layouts for usability issues
- Writing usability heuristic evaluations
- Generating interaction design specs
- Drafting UX research summaries

---

## Output Formats

Depending on what the user asks for, produce one of the following:

### User Flow Document
```
Flow Name: [Name]
Trigger: [What starts this flow]
Steps:
  1. [Screen/State] → [Action] → [Next Screen/State]
  2. ...
Edge Cases: [What can go wrong and how it's handled]
Success State: [What the user sees when done]
```

### Usability Review
```
Screen/Component: [Name]
Heuristic Violated: [Nielsen's heuristic name]
Severity: Low / Medium / High / Critical
Issue: [What's wrong]
Recommendation: [Specific fix]
```

### Interaction Spec
```
Component: [Name]
Default State: [Description]
Hover State: [Description]
Active State: [Description]
Disabled State: [Description]
Error State: [Description]
Transition: [Animation/timing details]
```

---

## Writing Guidelines

- Always describe UI in terms of **what the user experiences**, not just what it looks like
- Reference established UX patterns by name (e.g. progressive disclosure, skeleton screens)
- When reviewing designs, lead with the most critical issues first
- Be specific — avoid vague feedback like "make it cleaner"
- Always tie recommendations back to user goals or business outcomes

---

## Example Triggers

- "Write a user flow for onboarding"
- "Review this screen for usability issues"
- "Document the interaction states for this button"
- "Write a UX research summary"
- "Describe the UI for this feature"
